# 回复回合边界与 Framework7 交互接入（本地验收）

开始时 main 与 origin/main 一致，工作区干净。本次未 commit、push 或部署，只修改独立新版。未清空用户数据、改动存储名称或备份格式；测试使用独立浏览器 profile 和测试端口。旧站与 UI lab 源码未修改。

以上为本地验收时的状态。用户随后授权上传，最终提交和发布状态以 Git 历史及 GitHub Pages 构建记录为准。

## 用户确认的新边界

- 同一 conversationId + friendId 只有一条执行通道，不限制其他好友或其他会话并行。
- 等待首条实际输出时，新输入并入当前回合：不清除计时、不重新判断是否回复、不重抽数量、不推迟原回复。进入内容选择但仍未输出，也仍处于等待阶段。
- 首条输出后，新输入只形成一批待处理输入；当前轮包含文字和延迟贴图/表情及异步照片任务，全部结束后才启动一轮后续判断。
- 决定不回复或字卡不可用的一批输入正常结束，不把每条合并消息重新拿来补抽。
- 文字、组合贴图、图片和拍一拍等原 deferReply 入口共用上述通道；deferReply 指定的等待只用于新建的通道，不覆盖已有任务。
- 主动机会遇到同一角色忙碌时跳过，不积攒。420/120/45 分钟的机会公式不变。角色消息不引起无限回复。
- 正常导航不取消任务，删除、显式取消和系统长暂停仍按已有生命周期处理。
- 正在输入按好友 ID 去重；同名但不同 ID 不会错误合并。

数量表达式及图片、拍一拍、贴图、文字表情等每轮/每条分支未改。总体频率会受回合边界改变影响，不能说总体频率数学上完全未变。旧文档中“最短等待后解除合并”的说明已被本规则替代。

## Framework7 接入范围及气泡保护

使用本地 Framework7 9.0.0（MIT，许可证随资源保留）。资源构建脚本只读取 UI lab 的依赖，不引入它的模拟回复器或存储。不依赖运行时 CDN 加载 Framework7。

- 接入真实 Framework7 View/Router 的 iOS 页面进入、返回与 24px 边缘右滑。快速反向导航保留最后的界面意图。
- 使用 Framework7 官方消息位移动画，缩短到 180ms，不叠加原透明度入场；历史渲染不补播。减少动态效果时禁用消息入场并取消程序导航动画。
- 保留原消息 DOM、气泡 CSS、引用、图片、贴图、窗口化历史和发送事件。依用户追加要求，**不使用 Framework7 默认气泡组件/尺寸/配色**。没有新增一套消息发送逻辑。
- 输入栏仅接入 scoped Messagebar 外观；尺寸和键盘仍由 NextInput 统一管理，不初始化第二个 Messagebar resize/scroll 循环。
- 页面离开后原节点停放在不可见区域，保留旧功能所需 DOM ID，不销毁运行任务。返回主页后解除主页 inert，防止界面看得到却点不了。
- 旧皮肤设置与原 CSS 选择器不变，不包裹或重写气泡。保留每会话的字体、背景、颜色和自定义 CSS。

这不是把 Framework7 示例页面整套替换进来；外层四项导航和原聊天内容、皮肤仍保留。系统冻结后的后台限制和此前多标签页限制不因 UI 框架改变而消失。
