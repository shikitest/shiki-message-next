# 消息运行恢复：本地验收记录（2026-11-06）

本次只修改 shiki-message-next。基线为 8827d69；开始时工作区干净。本文为本地验收记录，用户随后另行授权提交和发布，具体发布状态以 Git 历史及 Pages 构建记录为准。没有读取或修改用户浏览器真实记录。自动化浏览器使用独立临时 profile、8873 端口和合成数据；原项目只读对照，shiki-chat-ui-lab 工作区未改动。

## 范围与原流程

没有替换整站框架，也没有增加第三套简化回复器。在现有 NextRuntime 好友适配层内修复归属与任务生命周期；继续复用 core.js 的 chooseReplyText、addMessage、createMessageFragment、消息窗口化渲染、原字卡编辑器、原随机图片生成与拍一拍内容选择。NextMessageStore 只是现有 chatMessages 的按会话追加适配器，未增加数据库或更改备份格式。

不声称整个旧 simulateReply 原封不动运行：它依赖全局当前角色、设置和消息数组，不能直接用于后台其他会话。此次把调用所需的设置、表情池、引用候选和会话/好友 ID 固定下来，仍使用既有概率表达式与内容来源。

## 已确认原因

1. next-runtime.js 原 applyCurrent 强制 autoSendEnabled=false；core.js 的 manageAutoSendTimer 检测新版后停止旧调度器。现在保留会话已存开关，使用全站唯一独立随机循环；关闭的会话不会被擅自开启。
2. 切换会话 cancelReplies、visibilitychange 清空任务、SESSION_ID/switchGeneration/document.hidden 执行门槛会丢弃有效回复。现在 UI 版本标记仅保护加载；回复绑定固定会话/好友。删除或恢复数据按相应会话/好友取消，正常导航不取消。
3. 多个图片/贴图/拍一拍入口用 setTimeout(simulateReply)，执行时会读取新会话。现在这些入口通过 deferReply 捕获原会话。
4. 每次打开表情栏重建全部贴图节点。现在每页首次 42 个，滚动分批追加，并缓存当前两种贴图库节点；图片异步解码、懒加载。没有删除贴图或禁用滚动。
5. 每次消息保存会重写未变化的贴图库等辅助数据。现在缓存成功写入的辅助值，变化后再写；加载/导入时失效。消息本身仍保存，失败写入不标记为已缓存。列表/主动检查使用轻量好友资料，避免为了查询名称反复复制整份字卡。
6. 新输入区 ResizeObserver/visualViewport 回调会直接读尺寸并写样式。现在每帧合并，尺寸未变不写，隐藏界面不测量。此项是减少重复布局工作；没有证据表明它是用户手机卡死的唯一原因。
7. 实际回归发现 NextMood 异步刷新会调用 applyCurrent，群聊中可能把正在编辑的好友字卡覆盖为空工作数组。现在编辑器存活时保留固定好友的工作数组；已加入“群聊编辑器打开后再 applyCurrent”的回归。

## 主动频率

用户确认以独立概率替代旧等待分布，并将低频中位时长改为 420 分钟，普通 120、高频 45。

设中位时长 M 分钟，检查间隔实际经过 t 秒，触发机会概率：`1 - 0.5 ** (t / (60*M))`。

| 频率 | M | 每分钟等价机会概率 | 正常 10 秒检查概率 |
| --- | ---: | ---: | ---: |
| 低 | 420 | 0.164899% | 0.027502% |
| 普通 | 120 | 0.575958% | 0.096224% |
| 高 | 45 | 1.528525% | 0.256392% |

每个启用会话的每名未删除成员各自抽签。检查频率变化时按实际经过时间换算，不进行逐个历史时间点补抽。中位时长指主动触发机会，不保证空字卡、开启已读不回等条件下实际收到文字的中位时间也完全相同。新分布与旧对数正态等待及连发机制不同，这是用户确认的调整，不宣称二者数学等价。

## 生命周期、持久化与边界

- 首页/好友/设置停留及 A/B 切换不取消任务。后台消息按原 ID 写原 chatMessages，摘要及未读更新；打开目标后清未读。
- 追加与既有 saveData 共用会话写队列；稳定消息 ID 去重。未被加载快照吸收的后台消息会合并，避免旧快照覆盖新追加。不会为后台发送临时切换全局会话。
- 页面隐藏不主动取消任务；页面关闭/pagehide、支持的 freeze/resume 事件会清理未完成任务，不重放。重开不读取历史调度时间表。
- 没有服务器推送。保活音频未改动，仍是辅助。不能承诺 iOS 锁屏或系统终止后持续执行。
- 不支持 freeze 事件的平台，用超过 90 秒的调度停顿作暂停判断，丢弃过期任务，不补发。浏览器不能完美区分节流与冻结，因此这是明确的启发式边界；没有真实手机长期验证。
- 多标签页同时打开同一站点可能各有一个运行循环；本次未实现跨标签页领导者选举，不宣称多标签完全无重复主动机会。试用时使用一个标签页。

## 动画与滚动

复用原 messageAppear，仅对新追加的可见消息加动画；历史重新渲染不播放整段入场。正在输入按会话/成员聚合并淡出；后台不渲染不可见消息，返回后恢复。查看历史时不强行跳到底部，显示“新消息”入口。近底部跟随；贴图预留 120px 容器并 contain，避免加载时改变气泡高度。尊重减少动态效果。
