# 系统与站内消息提醒：本地修复

保留当前未提交的回复回合与 Framework7 改动，未重置数据，未提交、推送或部署。

以上为本地验收时的状态。用户随后授权上传，最终提交和发布状态以 Git 历史及 GitHub Pages 构建记录为准。

## 原因

1. 新版权限按钮仅调用 Notification.requestPermission，没有写入旧通知函数必需的隔离存储键 notifEnabled。因此“权限已允许”不等于旧发送开关已开启。
2. 旧 _sendPartnerNotification 只处理 document.hidden，前台主页/其他会话没有站内消息横幅。
3. Service Worker 的点击处理只聚焦网页，没有携带或打开消息所属会话。

## 实现

- 所有提醒从 noteMessageSaved 接入：已落盘的新消息才通知；不扫描或重播历史。按会话 ID + 消息 ID 去重，内存去重上限 2000。旧零散系统通知调用在新版中不再重复发送。
- 当前可见聊天不弹重复横幅；主页、其他聊天、资料等页面收到消息显示站内提醒。横幅沿用原 notification 样式基础，增加头像、发送者、预览、关闭及打开对应会话。用户内容通过 textContent 呈现。
- 网页隐藏或不在焦点时，系统通知要求原 notifEnabled=1 且浏览器已授权。站内开关独立，不依赖系统权限。免打扰在两类提醒前检查。
- 一级设置的“通知与保活音频”内提供唯一系统开启/关闭入口和站内提醒开关。站内默认开启；系统仍须用户点击授权，不自动申请。沿用 NextStorage 隔离键，不访问旧站配置。
- 系统通知复用 BackgroundSupport / Service Worker。只等待新版注册的 worker，避免取到旧站根作用域注册；失败时尝试浏览器 Notification 回退。新 worker 允许本作用域更新立即激活，不清理缓存和数据库。
- 点击系统通知只聚焦新版作用域的页面，并通知页面打开固定 conversationId；没有窗口时使用一次性 query 标记，在初始化完成后打开目标并删除标记。普通打开网站仍默认聊天列表。
- 点击站内提醒保存原聊天草稿，关闭详情/设置覆盖层，打开正确会话。没有新增发送、概率、调度、气泡或备份改动。

## 验收

tools/check-notifications.cjs 使用独立 Chromium profile、8878 端口及合成资料：

- 实际 Runtime 回复保存后触发主页横幅；当前聊天抑制；其他聊天横幅点击与原草稿保存。
- 免打扰、站内开关、系统开关、重复消息去重、刷新持久化。
- 真实设置按钮切换原 notifEnabled 键；权限拒绝时站内仍可提醒。
- 后台系统发送参数、会话/消息 ID：通过拦截 BackgroundSupport 调用验证，未实际向用户设备投递系统弹窗。
- worker 点击聚焦/发消息的会话归属、排除旧站窗口、无窗口启动路由：使用 worker 模拟环境验证。
- 无新增浏览器未捕获错误；文本不能注入 HTML。
